# spmzone-rs

Rust port of `spmzone.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `SZTemp` (`spmzone.c:9`)
- `OAReset` (`spmzone.c:14`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports two of the set point managers in `src/EnergyPlus/SetPointManager.cc`, which
EnergyPlus runs at every HVAC iteration:

- `SPMSingleZoneTemp::calculate` (SetpointManager:SingleZone:Heating and :Cooling): the supply air
  temperature that meets the zone's load to its heating or cooling set point at the zone inlet
  flow (`psychrometrics-rs`, unit 1, for the specific heat), limited to the manager's minimum and
  maximum, or the limit itself with no flow;
- `SPMOutsideAir::calculate` (SetpointManager:OutdoorAirReset, used for hot water and supply air
  resets): the set point on the reset line that `interpSetPoint` evaluates at the outdoor
  temperature, held at its ends (their mean when the line is empty), the second line when the
  optional schedule is at 2.

The oracle (`rust/oracles/spmzone/`) sets up the zone's demand, the nodes, the outdoor temperature
and a constant schedule, then calls the real routines. These return NaN in both (ADR-009): a
schedule value other than 1 or 2 (a severe error), and any input that is not finite or lies
outside what EnergyPlus meets (see the shim).

Not ported yet: the schedule value error, the other set point managers and the node updates.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 109 lines of Rust (with tests) against
  a limit set by the 11-line C forwarder in `rust/oracles/spmzone/`. Waived under ADR-007.
- **Recording, diff and gate:** 14059 cases in all: 6750 cases of each manager, interleaved, plus
  rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the cases
  were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 14059/14059 match. The gate was run on a
  copy of this crate with the first 4000 cases (both managers): every check passes (behaviour
  4000/4000) except size.
- **Speed:** faster than the C++: `SZTemp` 1.22x (19 ns per call against 23 ns) and `OAReset`
  1.57x (18 ns against 28 ns), a few nanoseconds of which are the oracle's per-call setup. Timed by
  a direct in-process loop over the recorded cases, both sides called through a C function
  pointer, best of 15 interleaved runs.
