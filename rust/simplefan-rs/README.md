# simplefan-rs

Rust port of `simplefan.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `SimpleFan` (`simplefan.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `Fans::FanComponent::simulateConstant`, `simulateVAV` and `simulateOnOff` from
`src/EnergyPlus/Fans.cc`, which EnergyPlus runs for every Fan:ConstantVolume, Fan:VariableVolume
and Fan:OnOff at every HVAC iteration:

- the fan power from the design pressure rise, total efficiency and air density, the shaft power,
  the heat lost to the air (with the motor in or out of the air stream) and the outlet air state
  (`PsyTdbFnHW`, from `psychrometrics-rs`, unit 1, a path dependency);
- for variable volume fans, the part load curve over the flow fraction limited to the minimum flow
  fraction, with the pressure rise passed in or not, and below 10 % flow the linearised power when
  the air would heat by more than 20 C;
- for on/off fans, the runtime fraction from the coil's part load fraction (raised to 0.7, then
  reset to 1);
- the EMS overrides of mass flow, pressure rise and total efficiency, the availability schedule
  and the TurnFansOn and TurnFansOff globals, and the off state.

The oracle (`rust/oracles/simplefan/`) sets up one fan as `FanComponent::init` leaves it, then
calls the real simulate method. These return NaN in both (ADR-009): `which`, `kind`, `turn` or
`ems` out of range, and any input that is not finite or lies outside what EnergyPlus meets (see
the shim; the coil part load fraction is kept above 0, so its recurring warning never runs).

Not ported yet: night ventilation, fouled air filter faults, the on/off fan's speed ratio curves,
Fan:ZoneExhaust, Fan:ComponentModel, Fan:SystemModel, and `init`, `update` and `report`.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 318 lines of Rust (with tests) against a limit
  set by the 6-line C forwarder in `rust/oracles/simplefan/`. Waived under ADR-007.
- **Recording, diff and gate:** 13936 cases in all: 1500 fans, each asked for all nine results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13936/13936 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 1.37x faster than the C++: 51 ns per call against 70 ns. Timed by a direct in-process
  loop over the recorded cases, both sides called through a C function pointer, best of 15
  interleaved runs. The C++ side also builds a `FanComponent` (with its strings) per call, which
  EnergyPlus does once, so part of the gap is the oracle's set-up, not the fan model.
