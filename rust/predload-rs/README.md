# predload-rs

Rust port of `predload.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `PredictedSystemLoad` (`predload.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ZoneTempPredictorCorrector::ZoneSpaceHeatBalanceData::calcPredictedSystemLoad`
from `src/EnergyPlus/ZoneTempPredictorCorrector.cc` for a zone (not a space). The zone air heat
balance runs it for every controlled zone on every predictor step. It works out the loads to the
heating and cooling set points under the third order, analytical or Euler zone air solution:

- by thermostat type: uncontrolled, single heating, single cooling, single heating and cooling,
  or dual set point with deadband;
- divided by the RoomAirflowNetwork fraction when there is one (the single cooling case divides
  the heating load, which it then overwrites, as the C++ does);
- with the cooling load taken from the IT equipment return air temperature when the zone has it,
  after the first simulation step;
- in the deadband, the set point is the system node temperature trapped between the set points;
- a staged thermostat then replaces the loads by its stage.

Then come the node set point, the setback and deadband flags, and the zone demands with the load
correction factor and the zone and list multipliers
(`ZoneSystemSensibleDemand::reportSensibleLoadsZoneMultiplier`). `min` and `max` are ObjexxFCL's,
whose NaN handling the port keeps.

The oracle (`rust/oracles/predload/`) sets up one zone, then calls the real function. These
return NaN in both (ADR-009):

- flags outside 0 or 1, and thermostat types and algorithms outside their enums;
- multipliers outside 1 to 10000, whose int product must not overflow;
- a heating load above the cooling load, or loads that compare as neither (NaN), under a single
  heating and cooling or dual set point thermostat, which EnergyPlus stops on as fatal errors
  (the oracle catches the `FatalError`).

Not ported yet: spaces (`spaceNum > 0`) and copying the demands into the sequenced equipment
demands.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 290 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/predload/`. Waived under ADR-007.
- **Recording, diff and gate:** 12885 cases in all: 1250 zones, each asked for all ten results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 12885/12885 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 10.5x faster: 19 ns per call against 196 ns for the C++. Much of the C++ figure is
  the oracle: it writes about 25 state fields and enters a `try` block before each call. Timed by
  a direct in-process loop over the recorded cases, both sides called through a C function
  pointer, best of 15 interleaved runs.
