# sensout-rs

Rust port of `sensout.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `CompOutput` (`sensout.c:10`)
- `ZoneOutput` (`sensout.c:15`)
- `ZoneSensOutput` (`sensout.c:20`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports three routines from `src/EnergyPlus/GeneralRoutines.cc` that report the
sensible, latent and total rates of an air stream. Almost every coil, fan, heat exchanger and zone
equipment model calls them at every HVAC iteration:

- `CalcComponentSensibleLatentOutput`: across a component, the total rate from the enthalpy
  difference and the sensible rate at the lower of the two humidity ratios;
- `CalcZoneSensibleLatentOutput`: for supply air entering a zone, the sensible rate at the zone's
  humidity ratio;
- `calcZoneSensibleOutput`: the zone sensible rate alone;
- the latent rate is the total less the sensible, and all are zero with no flow
  (`psychrometrics-rs`, unit 1).

The oracle (`rust/oracles/sensout/`) calls the real routines and returns one result at a time.
These return NaN in both (ADR-009): any input that is not finite or lies outside what EnergyPlus
meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check, size included (78 lines of Rust for the
  16-line C forwarder).
- **Recording, diff and gate:** 14240 cases in all: 4500 of each routine, interleaved, plus
  rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the cases
  were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 14240/14240 match. The gate was run on a
  copy of this crate with the first 4000 cases (all three routines): behaviour 4000/4000.
- **Speed:** level with the C++: `CompOutput` 1.00x and `ZoneOutput` 0.98x (9 ns per call on both
  sides), `ZoneSensOutput` 0.92x (8 ns against 7 ns). The routines are a few multiplications, so
  the per-call overhead and input checks are most of it. Timed by a direct in-process loop over
  the recorded cases, both sides called through a C function pointer, best of 15 interleaved
  runs.
