# watercc-rs

Rust port of `watercc.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `WaterCoolCoil` (`watercc.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```
## What is ported

`src/port.rs` ports `CoolingCoil` from `src/EnergyPlus/WaterCoils.cc` with the simple analysis
(the Coil:Cooling:Water default), with `CoilCompletelyDry`, `CoilCompletelyWet`,
`WetCoilOutletCondition` and `CoilOutletStreamCondition`:

- a dry coil when the entering air's dew point is at or below the water temperature, by
  effectiveness-NTU for counter or cross flow at the dry UA;
- otherwise a completely wet coil: an enthalpy-based counterflow exchanger from the internal and
  external UAs, the surface temperature at the air inlet, and the outlet air state from the
  condensate temperature;
- cycling fan flows scaled by the part load ratio, the outlet water and air enthalpies.

The water specific heat comes from `halfloop-rs`'s cached lookup (unit 84), the air properties from
`psychrometrics-rs`. The detailed analysis (`CoilPartWetPartDry`) is not ported. The oracle
(`rust/oracles/watercc/`) calls the real routine on one coil and returns one result at a time; it
zeroes the coil's cooling rates first, which a coil that does not run leaves as they were. These
return NaN in both (ADR-009): any input that is not finite or lies outside what EnergyPlus meets
(see the shim).

`psychrometrics-rs` now keeps the C++ `cached_Tsat_HPb` table for `PsyTsatFnHPb`: the wet coil asks
for the saturation temperature of two enthalpies that can share a cache slot (with a near-zero
water-side UA), and the C++ then returns the first one's result for the second. The 22 cases that
showed it now match, and `psychrometrics-rs` (7844), `meanair-rs` (12884) and `oamixer-rs` (13805) still
match all their cases.

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (358 lines of Rust for the 6-line C
  forwarder, which hides five C++ routines). Waived under ADR-007.
- **Recording, diff and gate:** 13855 cases in all: 13500 real ones (1687 coils asked for all eight
  results, plus 4) and rust-anything's generated cases, recorded and diffed in chunks with the
  crate's own driver, from fresh chunk folders. All 13855/13855 match. The gate was run on a copy
  of this crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** 0.98x (87 ns per call against 85 ns): even. Two earlier runs gave 1.01x (with the
  cache) and 0.67x (before it, when every wet call iterated the saturation temperature). Timed by a
  direct in-process loop over the recorded cases, both sides called through a C function pointer,
  best of 15 interleaved runs; the C++ side's time includes the shim setting the coil's fields.
