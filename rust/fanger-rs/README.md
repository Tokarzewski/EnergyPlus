# fanger-rs

Rust port of `fanger.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `FangerPMV` (`fanger.c:9`)
- `StandardEffectiveTemp` (`fanger.c:14`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports from `src/EnergyPlus/ThermalComfort.cc`:

- `CalcFangerPMV`: Fanger's predicted mean vote with its clothing surface temperature
  iteration (up to 150 steps), as ANSI/ASHRAE 55 and ISO 7730 give it;
- `CalcStandardEffectiveTemp`: the Pierce two-node model's hour of minute-by-minute temperature
  regulation (vasomotion, sweating, shivering, skin wettedness), the effective temperature ET*
  and the standard effective temperature SET*.

EnergyPlus runs them for every People object with comfort reporting at every zone time step.
`PsyPsatFnTemp` comes from `psychrometrics-rs` (with the C++ saturation pressure cache) and
`CalcSatVapPressFromTempTorr` from `comfort-rs`; both are path dependencies.

The oracle (`rust/oracles/fanger/`) calls the real functions. These return NaN in both
(ADR-009): `which` out of range; and for `StandardEffectiveTemp`, whose iterations need not end
otherwise, any input that is not finite or lies outside what EnergyPlus can meet (air or radiant
temperature outside -40 to 60 C, humidity outside 0 to 1, air velocity outside 0 to 5 m/s,
activity outside 0.7 to 4 met, clothing outside 0 to 3 clo, work outside 0 to half the activity,
barometric pressure outside 60000 to 110000 Pa).

Not ported yet: the callers that pick the inputs from People objects (`CalcThermalComfortFanger`,
`CalcThermalComfortPierceASHRAE`) and the cooling effect and ankle draft models.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 402 lines of Rust (with tests) against
  a limit set by the 11-line C forwarder in `rust/oracles/fanger/`. Waived under ADR-007.
- **Recording, diff and gate:** 14151 cases in all: 1750 people asked for all four PMV results and
  1100 for all six SET results, plus rust-anything's generated cases. WSL kept going down and
  cutting long driver runs, so the cases were recorded and diffed in chunks of 1500 with the
  crate's own driver (`.rust-anything/driver_c.py record` and `diff`). All 14151/14151 match. The
  gate was run on a copy of this crate with the first 4000 cases: every check passes (behaviour
  4000/4000) except size.
- **Speed:** level with the C++. `FangerPMV` ran at 0.98x to 1.16x over five runs (about 205 ns
  per call each side), `StandardEffectiveTemp` at 1.02x (5.97 us against 6.09 us). Both spend
  their time in `pow`, `exp` and `sqrt` from the same C library, so there is little for Rust to
  win. Timed by a direct in-process loop over the recorded cases, both sides called through a C
  function pointer, best of 15 interleaved runs.
