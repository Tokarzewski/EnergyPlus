# pump-rs

Rust port of `pump.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `Pump` (`pump.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `Pumps::CalcPumps` from `src/EnergyPlus/Pumps.cc`, which EnergyPlus runs for
every pump on every plant loop side simulation, several times per HVAC iteration:

- the flow request bounded by the pump's limits (none for a series active variable speed or
  condensate pump) and passed through `SetComponentFlowRate` from `setflow-rs` (unit 65);
- the pumps running in a bank;
- the power from the cubic part load curve on the volume flow (the water density from
  `fluidproperties-rs`), for single pumps and banks with the last pump at part load, a negative
  power set to 0;
- the pressure-based power from the loop's pressure drop and the EMS pressure override;
- the shaft power, heat to the fluid and the outlet node's temperature and pressure.

The oracle (`rust/oracles/pump/`) sets up one pump as `InitializePumps` leaves it, alone on the
supply side's branch of a water plant loop, then calls the real routine. It runs with the warm-up
flag on, so the low flow constant speed warning (which changes no result) stays quiet. These
return NaN in both (ADR-009): flags out of range, and any input that is not finite or lies outside
what EnergyPlus meets (see the shim).

Not ported yet: the VFD speed (RPM) reporting, steam pumps, headered pump flow resolution in the
loop solver, `InitializePumps`, sizing, zone heat gains and reporting.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 265 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/pump/`. Waived under ADR-007.
- **Recording, diff and gate:** 13928 cases in all: 1227 pumps, each asked for all eleven results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13928/13928 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** faster than the C++, 2.06x to 2.48x over two runs on a loaded machine (73 ns per call
  against 151 ns in the quieter one). Much of the C++ side's time is the oracle's per-call setup
  of the pump, the loop and its nodes. Timed by a direct in-process loop over the recorded cases,
  both sides called through a C function pointer, best of 15 interleaved runs.
