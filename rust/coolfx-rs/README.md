# coolfx-rs

Rust port of `coolfx.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `CoolingEffect` (`coolfx.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ThermalComfort::CalcCoolingEffectAdjustedPMV` from
`src/EnergyPlus/ThermalComfort.cc` (ANSI/ASHRAE 55 Appendix D), which EnergyPlus runs for every
People object with the ASHRAE 55 cooling effect at every zone time step:

- the standard effective temperature and PMV at the relative air velocity;
- the cooling effect: the drop in air and radiant temperature that gives the same standard
  effective temperature in still air (0.1 m/s), found by `General::SolveRoot` between 0 and 50 C
  under the default root finder settings (regula falsi);
- the PMV adjusted for it, and its PPD.

It is built from earlier ports: `fanger-rs` (unit 58, whose `Person`, results and model functions
are now public for this), `solveroot-rs` (unit 12) and `comfort-rs` (unit 10, PPD and relative
air velocity). All are path dependencies.

The oracle (`rust/oracles/coolfx/`) sets up one People object's comfort inputs, then calls the
real `CalcCoolingEffectAdjustedPMV` and `CalcFangerPPD`. These return NaN in both (ADR-009):
`which` outside 0 to 2; and, as the standard effective temperature iterations need not end
otherwise, any input that is not finite or lies outside what EnergyPlus meets (air or radiant
temperature outside 10 to 40 C, as the root search goes 50 C below them; humidity outside 0 to
1; air velocity outside 0 to 5 m/s; activity outside 0.7 to 4 met; clothing outside 0 to 3 clo;
work outside 0 to half the activity; barometric pressure outside 60000 to 110000 Pa).

Not ported yet: the recurring warning when the root search fails (the cooling effect is then 0,
as here), the caller that reads the People object's schedules, and the ankle draft PPD.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 121 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/coolfx/`. Waived under ADR-007.
- **Recording, diff and gate:** 13780 cases in all: 4500 people, each asked for all three
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver
  runs, so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13780/13780 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** level with the C++, 0.98x: 43.1 us per call against 42.1 us. Each call runs the
  standard effective temperature model a dozen or more times, which spends its time in `pow` and
  `exp` from the same C library on both sides. Timed by a direct in-process loop over the
  recorded cases, both sides called through a C function pointer, best of 15 interleaved runs.
