# shadowsub-rs

Rust port of `shadowsub.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `ShadowSub` (`shadowsub.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports a receiving surface with one window or door, shaded by one or two
shadowing surfaces, as `src/EnergyPlus/SolarShading.cc` computes it: `SHADOW` (the shadow
projections and the receiving figure), `SHDGSS` with `MULTOL` (the general shadows, as in unit
31), `SHDSBS` (the subsurface's figure from its `ShadeV` vertices, its overlaps with those
shadows, its sunlit area taken off the receiving surface's, and `SurfSunlitFracWithoutReveal`)
and `SHDRVL` (the shading of the subsurface by its reveal, for rectangles and triangles, with its
`RevealStatus`), then both clamps. `DeterminePolygonOverlap` works on a figure table, and
`HTRANS1` into it leaves each figure's transmittance as the C++ does: the triangular reveal's
overlap reads the transmittances its two figures held before. The clipping is Sutherland-Hodgman
or SlaterBarsky, from units 28 and 29.

The oracle (`rust/oracles/shadowsub/`) gives the real `SHADOW` a sunlit base surface 1, up to two
heat transfer surfaces as its general shadowing surfaces and one subsurface on it with an opaque
construction (`TransDiff` 0), so `CalcInteriorSolarOverlaps`, which only windows that transmit
reach, is not run; the subsurface's sunlit area is the same either way. `MaxHCS` is 16, more than
the 14 figures this needs, so `TooManyFigures` cannot arise. `SurfSunlitFracWithoutReveal` and
`SurfWinRevealStatus` are zeroed on every call, since `SHDSBS` and `SHDRVL` write them only on
some paths. These return NaN in both (ADR-009): an `algo` outside 0 or 1; a caster count outside 1
or 2; vertex counts other than 3 or 4; vertices or origin past 30 m; local axis, sun or cosine
values past 1; schedule values outside [0, 1]; a reveal outside [0, 2] m; areas outside
[0, 1e6] (the subsurface's net area above 0, since it divides); and a sun so low over the
receiving plane that a projection passes 4.

## Accepted gate exceptions (2026-11-22)

- **Size:** `rust-anything gate` fails only its size check: about 1190 lines in `src/port.rs`
  against a limit set by the 6-line C forwarder in `rust/oracles/shadowsub/`. Waived under ADR-007.
- **Speed:** 1.43x faster: 1060 ns per call against 1511 ns for the C++ (both include the
  oracle's setup). Timed by a direct in-process loop over the recorded cases, both sides
  called through a C function pointer, best of 15 interleaved runs, as for units 30 and 31
  (`rust-anything bench` runs past an hour on these units).
