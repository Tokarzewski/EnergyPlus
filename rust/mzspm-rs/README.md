# mzspm-rs

Rust port of `mzspm.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `MZTemp` (`mzspm.c:9`)
- `MZHum` (`mzspm.c:14`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports the multizone set point managers from `src/EnergyPlus/SetPointManager.cc`,
run at every HVAC iteration for each air loop that uses them:

- `SPMMultiZoneTemp` (`SetpointManager:MultiZone:Heating:Average` and `:Cooling:Average`): the
  flow-weighted zone temperature plus the heating or cooling zones' load over their flow times the
  supply air specific heat, limited, and at the limit when the load is below 1 W;
- `SPMMultiZoneHum` (`:MinimumHumidity:Average`, `:MaximumHumidity:Average`, `:Humidity:Minimum`,
  `:Humidity:Maximum`): the average zone humidity ratio plus the moisture load over the flow, or the
  highest (lowest) humidity ratio any zone needs, limited.

Uses `psychrometrics-rs` (unit 1). `std::clamp` and ObjexxFCL `min` and `max` are written out as
the C++ library does them. The oracle (`rust/oracles/mzspm/`) builds each manager over an air loop
cooling up to four zones, calls `calculate` and returns its set point. These return NaN in both
(ADR-009): any input that is not finite or lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (251 lines of Rust for the 11-line C
  forwarder, which hides the two managers and the shim's per-zone arguments). Waived under ADR-007.
- **Recording, diff and gate:** 14284 cases in all: 13500 real ones (6750 of each manager,
  interleaved) and rust-anything's generated cases, recorded and diffed in chunks with the crate's
  own driver, from fresh chunk folders. All 14284/14284 match. The gate was run on a copy of this
  crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** level with the C++: `MZTemp` 0.87x and 1.10x in two runs (about 60 to 78 ns per call
  against 66 to 68 ns), `MZHum` 1.03x and 0.98x. Timed by a direct in-process loop over the
  recorded cases, both sides called through a C function pointer, best of 15 interleaved runs.
