# predhum-rs

Rust port of `predhum.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `PredictedHumidityRatio` (`predhum.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ZoneTempPredictorCorrector::ZoneSpaceHeatBalanceData::calcPredictedHumidityRatio`
from `src/EnergyPlus/ZoneTempPredictorCorrector.cc` for a zone (not a space). The zone air
moisture balance runs it for every zone on every predictor step:

- the humidistat set points: relative humidity, or dew points turned into relative humidity at
  the zone air temperature, then the EMS overrides; a humidifying set point above the
  dehumidifying one is brought down to it;
- the moisture balance coefficients from the latent gains and the infiltration, ventilation,
  cooling tower, earth tube, convection, mixing and outdoor air flows, and the air capacity from
  the air density, volume, moisture capacity multiplier and system time step;
- the moisture loads to both set points under the third order, analytical or Euler zone air
  solution, divided by the RoomAirflowNetwork fraction when there is one;
- the load the zone needs (humidify, dehumidify, or none in the deadband), and the demands with
  the zone and list multipliers (`ZoneSystemMoistureDemand::reportMoistLoadsZoneMultiplier`).

A zone with no humidistat gets no load. The psychrometric functions come from
`psychrometrics-rs` (a path dependency).

The oracle (`rust/oracles/predhum/`) sets up one zone, then calls the real function. These
return NaN in both (ADR-009):

- flags outside 0 or 1, and humidistat types and algorithms outside their enums;
- multipliers outside 1 to 10000, whose int product must not overflow;
- barometric pressures outside 10000 to 200000 Pa, and dew point set points that are not finite,
  for which `PsyWFnTdpPb`'s search never ends;
- a negative air density, and loads that compare as none of humidify, dehumidify or deadband
  (NaN), which EnergyPlus stops on as fatal errors (the oracle catches the `FatalError`).

Not ported yet: spaces, faulty humidistat offsets, latent sizing without a humidistat, the
AirflowNetwork and RoomAirflowNetwork moisture terms, and copying the demands into each piece of
zone equipment's demand.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 290 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/predhum/`. Waived under ADR-007.
- **Recording, diff and gate:** 12512 cases in all: 2000 zones, each asked for all six results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 12512/12512 match. The gate was run on a
  copy of this crate with the first 4000 cases (its `psychrometrics-rs` path made absolute):
  every check passes (behaviour 4000/4000) except size.
- **Speed:** 1.25x faster: 58 ns per call against 72 ns for the C++, whose figure includes the
  oracle's per-call setup. It ran at 0.83x until `psychrometrics-rs` kept the same saturation
  pressure cache as the C++ (2026-11-23). Timed by a direct in-process loop over the recorded cases, both sides called through a C
  function pointer, best of 15 interleaved runs.
