# halfloop-rs

Rust port of `halfloop.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `HalfLoop` (`halfloop.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `UpdateHalfLoopInletTemp` from `src/EnergyPlus/HVACInterfaceManager.cc`, which
every plant and condenser loop without a common pipe runs each time one half of it has been
simulated:

- the other half loop is a well-mixed tank of half the loop's mass, fed by the simulated side's
  outlet and heated by its pumps;
- its final and average temperatures over the system time step come from the exact solution, or
  the steady one when the exponent reaches 700, or a plain heat balance with no mass or no flow;
- they give the loop side inlet's m cp dT and M cp dT/dt, and the last time step's tank outlet
  temperature is taken from the last call when the time has moved on;
- the water specific heat comes from `fluidproperties-rs` (unit 13), cached by temperature as the
  C++ caches it.

The oracle (`rust/oracles/halfloop/`) calls the real routine on one water loop and returns one
result at a time. These return NaN in both (ADR-009): any input that is not finite or lies outside
what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (127 lines of Rust for the 6-line C
  forwarder, which hides the 90-line C++ routine). Waived under ADR-007.
- **Recording, diff and gate:** 13786 cases in all: 13500 real ones (2700 calls asked for all five
  results) and rust-anything's generated cases, recorded and diffed in chunks with the crate's own
  driver, from fresh chunk folders. All 13786/13786 match. The gate was run on a copy of this
  crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** 1.42x (31 ns per call against 44 ns). Timed by a direct in-process loop over the
  recorded cases, both sides called through a C function pointer, best of 15 interleaved runs.
