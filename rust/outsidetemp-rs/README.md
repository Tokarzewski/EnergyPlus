# outsidetemp-rs

Rust port of `outsidetemp.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `OutsideSurfTemp` (`outsidetemp.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```
## What is ported

`src/port.rs` ports `HeatBalanceSurfaceManager::CalcOutsideSurfTemp` from
`src/EnergyPlus/HeatBalanceSurfaceManager.cc` for a heat transfer surface: the outside face heat
balance that `CalcHeatBalanceOutsideSurf` runs for every exterior surface on every iteration.
It picks the equation by whether exterior movable insulation is present and whether the
construction conducts "quickly" (first cross CTF term above 0.01, so the inside face balance is
folded in), each with or without an other side conditions model and an embedded source or sink;
then it sets `SurfQdotRadOutRepPerArea` from the linearized radiation terms and, for a source or
sink, the three radiant system coefficients. Sky and ground temperatures come from the weather
unless a surrounding surfaces list or a ground surfaces list overrides them. Each sum keeps the
C++ order of terms. Not ported: the tubular daylighting dome case (`TDD_Dome`), which reads the
dome's diffuser surface.

The oracle (`rust/oracles/outsidetemp/`) sets one surface's terms (first CTF terms, convection
and radiation coefficients, CTF history parts, absorbed shortwave, inside face and zone air
temperatures, weather) and calls the real `CalcOutsideSurfTemp`. These return NaN in both
(ADR-009): flag arguments outside 0 or 1, and movable insulation on a construction with a source
or sink, which EnergyPlus reports as a severe error through an error file the oracle does not
set up. A surrounding surfaces list is given without sky or ground temperature schedules.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 270 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/outsidetemp/`. Waived under ADR-007.
- **Recording, diff and gate:** 12503 cases (2000 surfaces asked for all six outputs, plus
  rust-anything's generated ones). WSL went down every 15 to 20 minutes and cut long driver runs,
  so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`): 12503/12503 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) but
  size.
- **Speed:** 2.24x faster: 25 ns per call against 55 ns for the C++. Here the C++ side is mostly
  the oracle writing about 30 state fields before each call; the heat balance itself is a few
  dozen floating point operations either way. Timed by a direct in-process loop over the
  recorded cases, both sides called through a C function pointer, best of 15 interleaved runs,
  under heavy load from other work.
