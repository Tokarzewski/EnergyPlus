# extconv-rs

Rust port of `extconv.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `ExtConvCoeff` (`extconv.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `Convect::InitExtConvCoeff` from `src/EnergyPlus/ConvectionCoefficients.cc`
for a surface facing the outside air. The outside heat balance calls it for every exterior
surface on every iteration.

The outside convection coefficient comes from the model set on the surface or on its zone:

- a user value;
- ASHRAE simple (combined convection and radiation);
- TARP, ASHRAE TARP or BLAST: Sparrow forced convection, windward or leeward, plus TARP natural
  convection, using the movable insulation's sheltered face temperature;
- MoWiTT;
- DOE-2.

Next come the EMS override and the frame adjustment ratio. Last come the linearized radiation
coefficients to the sky, the ground (or a ground surfaces temperature), the air and any
surrounding surfaces list.

The correlations are `ConvectionCoefficients.cc`'s, and each keeps the C++ order of operations.
`pow` goes to the same C library on both sides. Not ported: Kiva foundations (they hand Kiva
closures instead of a value), scheduled and user curve coefficients, the adaptive convection
algorithm, and a surrounding surfaces sky temperature schedule.

The oracle (`rust/oracles/extconv/`) sets up one exterior surface and its weather, then calls the
real `InitExtConvCoeff`. These return NaN in both (ADR-009):

- flags outside 0 or 1;
- a roughness outside the six classes;
- a model outside the list above;
- a user value set on the zone.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 315 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/extconv/`. Waived under ADR-007.
- **Recording, diff and gate:** 12954 cases in all: 2500 surfaces, each asked for all five
  coefficients, plus rust-anything's generated cases. WSL kept going down and cutting long driver
  runs, so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 12954/12954 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 1.65x faster: 42 ns per call against 70 ns for the C++. The C++ figure includes the
  oracle writing about 25 state fields before each call. Timed by a direct in-process loop over
  the recorded cases, both sides called through a C function pointer, best of 15 interleaved
  runs.
