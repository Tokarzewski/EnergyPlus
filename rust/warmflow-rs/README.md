# warmflow-rs

Rust port of `warmflow.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `WarmFlow` (`warmflow.c:9`)
- `RABypass` (`warmflow.c:14`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports two set point managers from `src/EnergyPlus/SetPointManager.cc`:

- `SPMWarmestTempFlow` (`SetpointManager:WarmestTemperatureFlow`), run at every HVAC iteration on
  VAV air loops that reset supply temperature and fan flow together: the highest supply
  temperature and lowest flow fraction that meet every cooled zone's load, temperature first or flow
  first, each limited, both at their limits when the total cooling load is below 1 W, and the
  critical zone;
- `SPMReturnAirBypassFlow` (`SetpointManager:ReturnAirBypassFlow`): the return air bypass flow that
  mixes the supply air to the scheduled set point less the fan heat, limited to the total flow, with
  the return air temperature floored at 1 C in the division.

Uses `psychrometrics-rs` (unit 1). `std::clamp` and ObjexxFCL `max` are written out as the C++
library does them. The oracle (`rust/oracles/warmflow/`) builds each manager, calls `calculate` and
returns one result at a time. These return NaN in both (ADR-009): any input that is not finite or
lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (195 lines of Rust for the 11-line C
  forwarder, which hides the two managers and the shim's per-zone arguments). Waived under ADR-007.
- **Recording, diff and gate:** 14153 cases in all: 13500 real ones (3375 loops asked for all three
  warmest results, interleaved with 3375 bypass cases) and rust-anything's generated cases,
  recorded and diffed in chunks with the crate's own driver, from fresh chunk folders. All
  14153/14153 match. The gate was run on a copy of this crate with the first 4000 cases: behaviour
  4000/4000.
- **Speed:** `WarmFlow` 1.19x (56 ns per call against 66 ns), `RABypass` 2.47x (12 ns against 28
  ns; the C++ side's time includes the shim building the manager object). Timed by a direct
  in-process loop over the recorded cases, both sides called through a C function pointer, best of
  15 interleaved runs.
