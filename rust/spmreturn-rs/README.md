# spmreturn-rs

Rust port of `spmreturn.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `RetWater` (`spmreturn.c:9`)
- `SysNode` (`spmreturn.c:14`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports two set point managers from `src/EnergyPlus/SetPointManager.cc`:

- `SPMReturnWaterTemp` (`SetpointManager:ReturnTemperature:ChilledWater` and `:HotWater`), run for
  each plant loop that resets its supply temperature: the supply set point that keeps the loop's
  temperature difference and returns the water at the target (constant, scheduled or the return
  node's set point), limited, and at the limit with no flow or a reversed difference;
- `SPMSystemNode` (`SetpointManager:SystemNodeReset:Temperature` and `:Humidity`): the set point
  interpolated in a reference node's temperature or humidity ratio by `interpSetPoint`, the mean of
  the two set points when the references are equal or crossed.

`std::clamp` is written out as the C++ library does it. The oracle (`rust/oracles/spmreturn/`)
builds each manager, calls `calculate` and returns its set point; the return water manager's plant
loop is taken as already found, so its node check has run. These return NaN in both (ADR-009): any
input that is not finite or lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (103 lines of Rust for the 11-line C
  forwarder). Waived under ADR-007.
- **Recording, diff and gate:** 14032 cases in all: 13500 real ones (6750 of each manager,
  interleaved) and rust-anything's generated cases, recorded and diffed in chunks with the crate's
  own driver, from fresh chunk folders. All 14032/14032 match. The gate was run on a copy of this
  crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** `RetWater` 1.32x (5 ns per call against 7 ns), `SysNode` 1.87x (13 ns against 24 ns;
  the C++ side's time includes the shim building the manager object). Timed by a direct in-process
  loop over the recorded cases, both sides called through a C function pointer, best of 15
  interleaved runs.
