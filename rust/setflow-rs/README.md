# setflow-rs

Rust port of `setflow.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `SetFlow` (`setflow.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `PlantUtilities::SetComponentFlowRate` from `src/EnergyPlus/PlantUtilities.cc`,
which every plant component (pumps, boilers, chillers, water coils, heat exchangers and more) calls
whenever it asks for a flow, many times per plant loop iteration:

- the request recorded on the inlet node and the outlet's available limits passed on from the
  inlet's hardware and available limits;
- on an unlocked loop side: the flow taken as asked while the loop is still to be sized; for series
  active flow control, the highest request and the tightest limits of every component on the
  branch, with the whole branch set to that flow; otherwise the request bounded by the
  component's own limits; an EMS load override of zero shutting the flow off; flows below the mass
  flow tolerance taken as zero;
- on a locked loop side: the flow the loop solver already set on the inlet;
- whether a demand component's changed request needs the loop side simulated again.

The oracle (`rust/oracles/setflow/`) sets up one plant loop whose branch holds one to three
components in series on four nodes, then calls the real routine. These return NaN in both
(ADR-009): flags and indexes out of range, and any flow that is not finite or lies outside 0 to
1000 kg/s (a negative hardware maximum makes the C++ report a severe error once sizing is done).

Not ported yet: the severe error for a negative hardware maximum, `SetActuatedBranchFlowRate`,
`SetComponentFlowRate`'s callers' plant location lookups and the loop solver's flow resolution.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 225 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/setflow/`. Waived under ADR-007.
- **Recording, diff and gate:** 13985 cases in all: 750 branches, each asked for all eighteen
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver runs,
  so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13985/13985 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** level with the C++, 1.01x (55 ns per call on both sides); on both sides the per-call
  setup of the four nodes and the branch costs about as much as the routine itself. Timed by a
  direct in-process loop over the recorded cases, both sides called through a C function pointer,
  best of 15 interleaved runs.
