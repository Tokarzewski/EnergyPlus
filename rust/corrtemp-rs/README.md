# corrtemp-rs

Rust port of `corrtemp.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `CorrectAirTemp` (`corrtemp.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ZoneSpaceHeatBalanceData::correctAirTemp` from
`src/EnergyPlus/ZoneTempPredictorCorrector.cc` for one fully mixed zone. EnergyPlus runs it for
every zone at every system time step:

- the air power capacity from the zone volume, sensible capacity multiplier and air properties;
- the zone heat balance sums, through `zonesums-rs` (unit 48), whose zone, sums and
  `calc_zone_or_space_sums` are now public for this;
- the heat balance coefficients with and without system air flow, and the new zone air
  temperature under the third order, analytical and Euler algorithms, from the zone or the system
  time step history;
- the sensible load with its air system heating and cooling rates and energies;
- the humidity correction, through `corrhum-rs` (unit 43), whose zone and `correct_hum_rat` are
  now public for this, with the new relative humidity and the system node's conditions;
- the returned temperature change that shortens the system time step.

The psychrometric functions come from `psychrometrics-rs`. All three crates are path
dependencies.

The oracle (`rust/oracles/corrtemp/`) sets up one zone with one space without heat transfer
surfaces, then calls the real `correctAirTemp`. These return NaN in both (ADR-009): `which`
outside 0 to 13, a flag outside 0 or 1, `algo` outside 0 to 2, `ndev` or `ninlets` outside 0 to
2, `mult` or `listmult` outside 1 to 10000, and the fatal error EnergyPlus stops on, a negative
air density.

Not ported yet: room air models other than fully mixed, the airflow network and duct loss terms,
the hybrid model, spaces, plenum zones, latent sizing, and surface convection (unit 40,
`sumhat-rs`, is not wired in: the oracle zone has no surfaces).

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 407 lines of Rust (with tests)
  against a limit set by the 6-line C forwarder in `rust/oracles/corrtemp/`. Waived under ADR-007.
- **Recording, diff and gate:** 13277 cases in all: 900 zones, each asked for all fourteen
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver
  runs, so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13277/13277 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 1.23x faster: 115 ns per call against 142 ns for the C++, whose call also sets the
  zone up. Most of both is psychrometrics: two air densities, the saturation humidity ratio and
  the relative humidity. Timed by a direct in-process loop over the recorded cases, both sides
  called through a C function pointer, best of 15 interleaved runs.
