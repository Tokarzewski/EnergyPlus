# supplenum-rs

Rust port of `supplenum.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `SupPlenum` (`supplenum.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `CalcAirZoneSupplyPlenum` followed by `UpdateAirZoneSupplyPlenum` from
`src/EnergyPlus/ZonePlenum.cc`, which every air loop with a supply plenum runs twice per pass of its
supply path:

- first pass: the plenum zone's temperature, humidity ratio and enthalpy go to every outlet node;
- second pass: the outlets' flows and available flows are summed back to the inlet and zone nodes,
  and the inlet is flagged as changed when its flow moves by more than 0.01 kg/s.

The oracle (`rust/oracles/supplenum/`) calls the real routines on one plenum with up to four outlets
and returns one result at a time. The contaminant models are off. These return NaN in both
(ADR-009): any input that is not finite or lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (111 lines of Rust against the 6-line
  C forwarder, which hides the two C++ routines and the shim's 21 arguments). Waived under ADR-007.
- **Recording, diff and gate:** 13884 cases in all: 13500 real ones (843 plenums asked for both
  passes and all eight results, plus 12) and rust-anything's generated cases, recorded and diffed
  in chunks with the crate's own driver, from fresh chunk folders. All 13884/13884 match. The gate
  was run on a copy of this crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** 6.68x (C++ 296 ns per call, Rust 44 ns), but the figure flatters the port: the C++
  side's time includes the shim resetting the zone and four outlet nodes on every call, which a
  real simulation does not do. The routines themselves are a few copies and sums. Timed by a
  direct in-process loop over the recorded cases, both sides called through a C function pointer,
  best of 15 interleaved runs.
