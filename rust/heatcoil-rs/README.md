# heatcoil-rs

Rust port of `heatcoil.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `HeatCoil` (`heatcoil.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `HeatingCoils::CalcElectricHeatingCoil` and `CalcFuelHeatingCoil` from
`src/EnergyPlus/HeatingCoils.cc`, which EnergyPlus runs for every Coil:Heating:Electric and
Coil:Heating:Fuel at every HVAC iteration:

- the load the coil delivers, asked for a load or for its set point (`SensedLoadFlagValue`, with
  the temperature control tolerance), limited by its capacity, and the outlet air temperature;
- for the electric coil, the cycling fan's flow and load scaled by the part load ratio (as the
  C++ changes the caller's `QCoilReq`), the electric use and runtime fraction;
- for the fuel coil, the fuel use, parasitic electric load and parasitic fuel rate, and with a
  part load fraction curve (a quadratic, as `Curve::value` evaluates it with input limits 0 to 1)
  the runtime fraction, the fuel use at it and the on/off fan part load fraction it passes on;
- the outlet enthalpy (`PsyCpAirFnW` and `PsyHFnTdbW` from `psychrometrics-rs`, unit 1, a path
  dependency) and the electric heating coil power global.

The oracle (`rust/oracles/heatcoil/`) sets up one coil as `InitHeatingCoil` leaves it, with a
constant availability schedule and a quadratic curve made by `Curve::AddCurve`, then calls the real
routine. These return NaN in both (ADR-009): flags out of range, any input that is not finite or
lies outside what EnergyPlus meets (see the shim), and part load fraction curves under 0.7 or
under the part load ratio somewhere on 0 to 1, for which the C++ warns.

Not ported yet: the warnings for such curves, the coil supply air temperature sensor fault,
multi-stage and desuperheater coils, other curve types, and `InitHeatingCoil` and reporting.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 253 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/heatcoil/`. Waived under ADR-007.
- **Recording, diff and gate:** 13863 cases in all: 1350 coils, each asked for all ten results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13863/13863 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 3.58x faster than the C++: 33 ns per call against 119 ns. Most of the gap is the
  oracle's set-up, not the coil model: the C++ side resets the whole coil object (strings and
  multi-stage arrays) on every call, which EnergyPlus does once. Timed by a direct in-process loop
  over the recorded cases, both sides called through a C function pointer, best of 15 interleaved
  runs.
