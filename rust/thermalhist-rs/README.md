# thermalhist-rs

Rust port of `thermalhist.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `ThermalHist` (`thermalhist.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `HeatBalanceSurfaceManager::UpdateThermalHistories` from
`src/EnergyPlus/HeatBalanceSurfaceManager.cc` for one opaque surface. The heat balance runs it
once per zone time step for every surface. It does two things:

- It sets the current inside and outside conduction fluxes from the first CTF terms, along with
  the face conduction outputs. With an embedded source or sink, it also sets the source and user
  location temperatures.
- It shifts the histories. In a "simple CTF" model, every temperature and flux history moves on
  by one term, up to the model's longest construction. Otherwise the master histories move on at
  the end of each construction time step, and in between the surface's histories are
  interpolated between master terms. The source, source flux and user location histories follow
  the same scheme.

Each expression keeps the C++ order of terms. EMPD surfaces are updated like CTF surfaces, and
CondFD surfaces are skipped, as in the C++.

The oracle (`rust/oracles/thermalhist/`) sets up one zone, one space and one surface, then calls
the real `UpdateThermalHistories`. It sets the construction's first CTF terms, history count and
time step, plus the model flags (`MaxCTFTerms`, `SimpleCTFOnly`, construction overrides, any
internal source). The surface's history values (eight histories and six source histories, terms
1 to 8, and the first-of-series values) come from a splitmix64 draw on a seed argument, and the
port repeats that draw. These inputs return NaN in both (ADR-009), because EnergyPlus never sets
them up:

- flags outside 0 or 1;
- more than 7 CTF terms, or more terms than the model shifts;
- a series position outside the construction's histories;
- a source or sink in a model with no internal sources.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 370 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/thermalhist/`. Waived under ADR-007.
- **Recording, diff and gate:** 11733 cases in all: 500 surfaces, each asked for the face outputs,
  its series position and a sample of history terms, plus rust-anything's generated cases. WSL
  kept going down and cutting long driver runs, so the cases were recorded and diffed in chunks
  of 1500 with the crate's own driver (`.rust-anything/driver_c.py record` and `diff`). All
  11733/11733 match. The gate was run on a copy of this crate with the first 4000 cases: every
  check passes (behaviour 4000/4000) except size.
- **Speed:** 1.20x faster: 209 ns per call against 251 ns for the C++. Both sides spend most of
  that drawing the 125 history values; the update itself is a few dozen operations. Timed by a
  direct in-process loop over the recorded cases, both sides called through a C function
  pointer, best of 15 interleaved runs.
