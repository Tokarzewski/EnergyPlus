# commonpipe-rs

Rust port of `commonpipe.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `CommonPipe` (`commonpipe.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `UpdateCommonPipe` from `src/EnergyPlus/HVACInterfaceManager.cc` with a single
common pipe, and through it `ManageSingleCommonPipe`, which primary-secondary plant loops run
after simulating each half:

- the other side's tank (a quarter of the loop's mass on the demand side's outlet, three quarters
  on the supply side's) over the system time step, by the exact solution or a heat balance;
- the flow in the common pipe: primary recirculation when the primary flow is larger, secondary
  when the secondary is, none when they are equal or differ by less than the mass flow tolerance;
- the mixed inlet temperatures of both sides and the common pipe's flow, temperature and direction.

The water specific heat comes from `halfloop-rs`'s cached lookup (unit 84). The two-way common pipe
is not ported. The oracle (`rust/oracles/commonpipe/`) calls the real routine on one water loop,
after the common pipes have been set up, and returns one result at a time. These return NaN in
both (ADR-009): any input that is not finite or lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (187 lines of Rust for the 6-line C
  forwarder, which hides the two C++ routines). Waived under ADR-007.
- **Recording, diff and gate:** 13805 cases in all: 13500 real ones (1687 calls asked for all eight
  results, plus 4) and rust-anything's generated cases, recorded and diffed in chunks with the
  crate's own driver, from fresh chunk folders. All 13805/13805 match. The gate was run on a copy
  of this crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** 5.97x (33 ns per call against 196 ns), but the figure flatters the port: the C++ side's
  time includes the shim resetting four nodes and the common pipe before each call, which a
  simulation does not do. Timed by a direct in-process loop over the recorded cases, both sides
  called through a C function pointer, best of 15 interleaved runs.
