# retplenum-rs

Rust port of `retplenum.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `RetPlenum` (`retplenum.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `CalcAirZoneReturnPlenum` from `src/EnergyPlus/ZonePlenum.cc`, which every air
loop with a return plenum runs on each pass of its return path:

- the outlet flow and available flows are the sums of the inlets';
- the outlet pressure is the inlets' pressures weighted by their flows, or the first inlet's when
  nothing flows;
- terminal units with an upstream, downstream or parallel PIU leak add their leak flows and their
  changes to the available flows;
- the induced air drawn from the plenum is subtracted;
- the outlet air takes the plenum zone's temperature, humidity ratio and enthalpy, and the
  maximum available flow is raised to the flow where it falls short (ObjexxFCL `max`).

The oracle (`rust/oracles/retplenum/`) calls the real routine on one plenum with up to four inlets,
two leaking terminal units and two induced-air outlets, and returns one result at a time. These
return NaN in both (ADR-009): any input that is not finite or lies outside what EnergyPlus meets
(see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size: 236 lines of Rust against the
  6-line C forwarder, which hides the 80-line C++ routine and the shim's 39 arguments. Waived
  under ADR-007.
- **Recording, diff and gate:** 14039 cases in all: 13500 real ones (1500 plenums asked for all
  seven results, and 3000 more for the flows and pressure) plus rust-anything's generated cases,
  recorded and diffed in chunks with the crate's own driver. All 14039/14039 match. The gate was
  run on a copy of this crate with the first 4000 cases: behaviour 4000/4000.
- **Speed:** 1.05x (C++ 122 ns per call, Rust 117 ns). Most of each call is passing and checking
  39 arguments; the routine itself is a few sums. Timed by a direct in-process loop over the
  recorded cases, both sides called through a C function pointer, best of 15 interleaved runs.
