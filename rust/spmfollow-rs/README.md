# spmfollow-rs

Rust port of `spmfollow.c`, bridged with the C ABI. Generated by rust-anything.

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports five set point manager calculations from `src/EnergyPlus/SetPointManager.cc`,
run at every HVAC iteration for each manager of their kind:

- `SPMSingleZoneOneStageCooling` and `SPMSingleZoneOneStageHeating`: the on or off set point by the
  zone's thermostat stage;
- `SPMSingleZoneHum` (minimum and maximum): the zone humidity ratio plus the moisture load over the
  supply flow, floored at 0 or 0.00001, and 0 below the small-flow cutoff;
- `SPMOutsideAirPretreat`: the outdoor set point that mixes with the return air to the reference
  set point, limited, the reference passed through with no flow and a zero humidity set point
  passed through as off;
- `SPMFollowOutsideAirTemp` and `SPMFollowSysNodeTemp`: the outdoor or a node's dry or wet bulb
  plus an offset, limited (a node's wet bulb is 0 without the extra node data).

`std::clamp` and ObjexxFCL `max` are written out as the C++ library does them. The oracle
(`rust/oracles/spmfollow/`) builds each manager, calls `calculate` and returns its set point. The
pretreat manager's missing-set-point check is taken as already run. These return NaN in both
(ADR-009): any input that is not finite or lies outside what EnergyPlus meets (see the shim).

## Gate (2026-11-23)

- **Gate:** `rust-anything gate` passes every check but size (131 lines of Rust for the 26-line C
  forwarder). Waived under ADR-007.
- **Recording, diff and gate:** 14748 cases in all: 13500 real ones (2700 of each manager,
  interleaved) and rust-anything's generated cases, recorded and diffed in chunks with the crate's
  own driver, from fresh chunk folders. All 14748/14748 match. The gate was run on a copy of this
  crate with the first 4000 cases (all five): behaviour 4000/4000.
- **Speed:** `FollowOA` 1.54x, `FollowNode` 2.64x, `SZHum` 2.74x, `OneStage` 3.36x, `Pretreat`
  16.4x, but the C++ side's time includes the shim building a manager object (with its strings) on
  every call, and for `Pretreat` resetting four nodes, which a simulation does not do; the
  calculations themselves are a few operations, so these are not real gains. Timed by a direct
  in-process loop over the recorded cases, both sides called through a C function pointer, best of
  15 interleaved runs.
