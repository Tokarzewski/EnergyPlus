# vert-fluid-rs

Rust port of `vertfluid.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `VFConvectionResistance` (`vertfluid.c:15`)
- `VFPipeResistance` (`vertfluid.c:20`)
- `VFBoreholeResistance` (`vertfluid.c:25`)
- `VFShortSteps` (`vertfluid.c:30`)
- `VFShortGFunction` (`vertfluid.c:35`)
- `VFShortLntts` (`vertfluid.c:40`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports the code of `GLHEVert` in `src/EnergyPlus/GroundHeatExchangers/Vertical.cc`
that reads the plant loop's fluid: `calcPipeConvectionResistance`, `calcPipeResistance`,
`calcBHAverageResistance`, `calcBHTotalInternalResistance`, `calcBHGroutResistance`,
`calcHXResistance` and `calcShortTimestepGFunctions` (with `TDMA` from `Base.cc`), with the
borehole and its multipole constants set up as the `GLHEVert` constructor sets them. The fluid is
water, through `fluidproperties-rs`; the friction factor and pipe conduction come from `vert-rs`.
The oracle (`rust/oracles/vertfluid/`) builds one plant loop of water and one inlet node, as the
Slinky unit test does. It takes at most 20000 short time steps; a longer run, no boreholes or a
step past the end returns NaN (ADR-009).

The short-time-step matrix and the forward sweep of `TDMA` do not change between time steps, so
the port works them out once; the C++ recomputes the same values every step. That makes a short
g-function about 80 times faster than the C++.

## Accepted gate exceptions (2026-11-22)

- **Size:** `rust-anything gate` fails only its size check: about 450 lines in `src/port.rs`
  (with tests) against a limit set by the 31-line C forwarder in `rust/oracles/vertfluid/`, not
  by the roughly 250 lines of real code ported. Waived under ADR-007.
