# vert-gfunc-rs

Rust port of `vertgfunc.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `VGCombinedLen` (`vertgfunc.c:12`)
- `VGCombinedLntts` (`vertgfunc.c:17`)
- `VGCombinedGFunction` (`vertgfunc.c:22`)
- `VGGFunc` (`vertgfunc.c:27`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `GLHEVert::calcGFunctions` with the uniform heat flux method and
`combineShortAndLongTimestepGFunctions` from `src/EnergyPlus/GroundHeatExchangers/Vertical.cc`,
and `getGFunc` with `GLHEBase::interpGFunc` from `Base.cc`. The short time steps come from
`vert-fluid-rs` and the long ones from `vert-rs`; only the long values the combined curve keeps
are worked out (the C++ computes them all and drops the ones the short steps cover).

The oracle (`rust/oracles/vertgfunc/`) builds an nx by ny field on a plant loop of water. Its
domain (ADR-009): 1 or 2 boreholes each way, at most 20000 short and 60 long steps, and a
combined LNTTS vector of at least two values with no NaN (`interpGFunc`'s `std::upper_bound`
needs a sorted range and reads both ends). Outside it, results are NaN or 0.

`interp` (`interpGFunc`) is public for `glhe-sim-rs`.

## Accepted gate exceptions (2026-11-22)

- **Size:** `rust-anything gate` fails only its size check: about 320 lines in `src/port.rs`
  against a limit set by the 21-line C forwarder in `rust/oracles/vertgfunc/`, most of them the
  plain-number signatures of the four exports. Waived under ADR-007.
- **erfc:** the long values use `libm`'s `erfc` through `vert-rs` (ADR-006), but none of the 1841
  recorded cases differs from the C++.
