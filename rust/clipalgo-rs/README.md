# clipalgo-rs

Rust port of `clipalgo.c`, bridged with the C ABI. Generated by rust-anything.

- `ClipOverlap` (`clipalgo.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports the polygon overlap of `src/EnergyPlus/SolarShading.cc` under all three
`ShadowCalculation` clipping algorithms: `SutherlandHodgman` (`CLIPPOLY`, as in unit 28),
`SlaterBarskyandSutherlandHodgman` (`CLIPPOLY` handing an axis-aligned rectangle clip to
`CLIPRECT` and its Liang-Barsky segment clipper `CLIPLINE`) and `ConvexWeilerAtherton` (`INCLOS`,
the enclosed vertices; `INTCPT`, the side intercepts in `Int64`; `ORDER`, the clockwise sort),
with `HTRANS1`, `HTRANS0` and `DeterminePolygonOverlap` around them. The homogeneous sides that
`CLIPRECT` recomputes at its end are not ported: `DeterminePolygonOverlap` never reads them again.

The oracle (`rust/oracles/clipalgo/`) loads two polygons of 3 or 4 vertices into figures 1 and 2,
sets the algorithm (`algo` 0, 1 or 2) and overlaps figure 2 on figure 1 into figure 3, sizing and
zeroing the figure and scratch arrays on every call. These return NaN in both (ADR-009): an
`algo` outside 0 to 2; vertex counts other than 3 or 4; coordinates that are not finite or lie
past 1000 m; and, for `ConvexWeilerAtherton`, coordinates past 10 m, since `INTCPT` multiplies a
side's constant term by another side's coefficient in `Int64` and overflows beyond that. `ORDER`
sizes `SLOPE` to 10 entries; the oracle sizes it to 16 so that overlaps of 11 to 14 vertices stay
in bounds. The port uses fixed stack arrays of 66 entries where the C++ grows its heap scratch
arrays: Sutherland-Hodgman at most doubles the vertex count per clipping side, so 4 vertices
clipped by 4 sides never pass 64.

## Accepted gate exceptions (2026-11-22)

- **Size:** `rust-anything gate` fails only its size check: about 820 lines in `src/port.rs`
  against a limit set by the 6-line C forwarder in `rust/oracles/clipalgo/`. Waived under ADR-007.
- **Speed:** 1.84x faster: 306 ns per call against 564 ns for the C++, across all three
  algorithms (both include the oracle's setup; the shim sizes and zeroes the figure arrays on
  every call). The fixed stack arrays do most of it: unit 28's port, which allocates its
  scratch vectors per call, is 0.89x. Other sessions were building in the same WSL (load
  average 13 to 38 on 24 cores), so the timings carry some noise.
