# vent-rs

Rust port of `vent.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `Ventilation` (`vent.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports the ventilation part of `ZoneEquipmentManager::CalcAirFlowSimple` from
`src/EnergyPlus/ZoneEquipmentManager.cc` for one zone with one ventilation object. EnergyPlus
runs it for every zone at every system time step:

- the design flow rate model (`ZoneVentilation:DesignFlowRate`) with its fan power, ventilation
  fan electricity and the heating of intake and balanced fans;
- the wind and stack open area model (`ZoneVentilation:WindandStackOpenArea`), with opening
  effectiveness and discharge coefficient given or autocalculated;
- the indoor, outdoor and delta temperature limits (values or schedules), the wind speed limit,
  hybrid ventilation closing, EMS overrides, the three density bases and the zone's outdoor air
  node;
- the zone's ventilation sums (`MCPV`, `VAMFL`, `MCPTV`).

The psychrometric functions come from `psychrometrics-rs` (a path dependency).

The oracle (`rust/oracles/vent/`) sets up one zone with simple air flows and only this
ventilation object, then calls the real `CalcAirFlowSimple`. These return NaN in both (ADR-009):
`which` outside 0 to 7, the object count outside 0 or 1, a model, density basis, fan type or
hybrid control outside its range here, a flag outside 0 or 1, scheduled minimum temperatures above
their maximums (EnergyPlus warns and changes them, which needs the error file), and the fatal error
EnergyPlus stops on, a negative air density.

Not ported yet: global hybrid ventilation control, the zone air balance (quadrature) sums,
AirflowNetwork fan scheduling of the fan electricity, space heat balance, and the warning path for
scheduled limits that cross.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 388 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/vent/`. Waived under ADR-007.
- **Recording, diff and gate:** 14192 cases in all: 1700 zones, each asked for all eight results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 14192/14192 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 2.67x faster: 27 ns per call against 72 ns for the C++, whose call also resets the
  zone's other air flow sums. Timed by a direct in-process loop over the recorded cases, both
  sides called through a C function pointer, best of 15 interleaved runs.
