# glhe-sim-rs

Rust port of `glhesim.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `GSRun` (`glhesim.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `GLHEBase::calcGroundHeatExchanger` and `calcAggregateLoad` from
`src/EnergyPlus/GroundHeatExchangers/Base.cc`: the time stepping of a ground heat exchanger with
sub-hourly, hourly and monthly load aggregation and g-function superposition, with `GLHEVert`'s
`getAnnualTimeConstant`, `getGFunc` and `calcHXResistance`. The HX resistance comes from
`vert-fluid-rs` and `interpGFunc` from `vert-gfunc-rs`.

The oracle (`rust/oracles/glhesim/`) runs the real code for up to 6000 time steps on a plant
loop of water, with a given g-function curve (units 14 to 16 port its computation), a load
pattern of its own and WarmupFlag on (so the design-day reset never fires). See the shim for the
exact clock, inlet temperature and flow of each step.

Water's specific heat goes through a copy of the glycol's specific heat cache
(`EP_cache_GlycolSpecificHeat`): over many time steps it returns an earlier temperature's value
for a temperature that shares the cache key. Four recorded runs have inlet swings that small;
with the raw lookup instead of the cache, two of their results differ in the last digits.

## Accepted gate exceptions (2026-11-22)

- **Size:** `rust-anything gate` fails only its size check: about 400 lines in `src/port.rs`
  against a limit set by the 6-line C forwarder in `rust/oracles/glhesim/`, not by the roughly
  280 lines of `Base.cc` ported. Waived under ADR-007.
- **Speed:** `bench` measures a tie (1.01x): both spend their time in the same g-function
  lookups and logarithms.
