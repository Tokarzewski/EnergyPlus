# zonemrt-rs

Rust port of `zonemrt.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `ZoneMRT` (`zonemrt.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `HeatBalanceSurfaceManager::CalculateZoneMRT` from
`src/EnergyPlus/HeatBalanceSurfaceManager.cc` for a zone of two spaces, each its own radiant
enclosure. The inside heat balance runs it on every iteration. It does three things:

- It works out each surface's area-emissivity weight, summed for the zone and for each
  enclosure.
- It sets the zone's mean radiant temperature. When the zone's weights sum to 0.01 or less, the
  zone's air temperature is used instead.
- It sets each enclosure's MRT, which is also its space's MRT. When the enclosure's weights sum to
  0.01 or less, the space's volume-weighted air temperature is used instead (its plain air
  temperature at volumes of 0.01 or less).

Every sum runs in the C++ order. One effect of that order is kept: an enclosure whose weights fall
back still carries the area-emissivity-temperature sum the zone loop added to it. Not ported: the
user zone MRT objects (`ComfortViewFactorAngles`-based people MRT splits), which the first call
reads from the input file, and the `ZoneToResimulate` form.

The oracle (`rust/oracles/zonemrt/`) sets up the zone, its spaces and up to six surfaces, then
calls the real `CalculateZoneMRT`. These return NaN in both (ADR-009):

- a result index outside 0 to 10;
- a negative surface count;
- more than six surfaces.

Each count is checked before they are added, so the C++ guard cannot overflow. An earlier version
of the guard added the counts first; rust-anything's generated cases near `INT_MAX` then overflowed
it (undefined behaviour) and the C++ read past the surface arrays. That was fixed in the oracle,
and every case was recorded again.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 170 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/zonemrt/`. Waived under ADR-007.
- **Recording, diff and gate:** 12525 cases in all: 1100 zones, each asked for all eleven results,
  plus rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 12525/12525 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 1.65x faster: 47 ns per call against 78 ns for the C++. The C++ figure includes the
  oracle setting up the surfaces and enclosures before each call. Timed by a direct in-process
  loop over the recorded cases, both sides called through a C function pointer, best of 15
  interleaved runs.
