# boiler-rs

Rust port of `boiler.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `Boiler` (`boiler.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `Boilers::BoilerSpecs::CalcBoilerModel` from `src/EnergyPlus/Boilers.cc`, which
EnergyPlus runs for every Boiler:HotWater each time the plant loop asks it for a load, many times
per HVAC time step:

- the early exit with no load or when off (series active control keeps the inlet flow);
- on an unlocked loop side, the design flow (constant and not modulated) or the flow that meets
  the load at the outlet set point (leaving set point modulated, single or dual set point loops),
  through `SetComponentFlowRate` from `setflow-rs` (unit 65, its items made public), and the
  outlet temperature;
- on a locked loop side, the load limited by the part load ratios at the inlet flow;
- the outlet temperature limit, the part load ratio, the normalised efficiency curve (none, a
  quadratic in the part load ratio, or a biquadratic with the entering or leaving water
  temperature, as `Curve::value` evaluates them with their input limits), the fuel use and the
  parasitic electric power and fuel rate;
- the water specific heat from `fluidproperties-rs` (unit 2, with a one entry cache like the
  C++'s by temperature).

The oracle (`rust/oracles/boiler/`) sets up one boiler as `InitBoiler` leaves it, alone on a
branch of a water loop, then calls the real routine. It runs with the warm-up flag on, so the
curve output warnings are skipped, and with them the resets of the curve output to 0.01 and 1.1;
the port does the same. These return NaN in both (ADR-009): flags out of range, and any input that
is not finite or lies outside what EnergyPlus meets (see the shim).

Not ported yet: the curve output warnings and resets outside warm-up, the boiler fouling fault,
other curve types and output limits, `InitBoiler`, sizing and `UpdateBoilerRecords`.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 306 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/boiler/`. Waived under ADR-007.
- **Recording, diff and gate:** 13956 cases in all: 1227 boilers, each asked for all eleven
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver runs,
  so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13956/13956 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** faster than the C++, 1.55x: 59 ns per call against 92 ns. Part of the C++ side's time
  is the oracle's per-call setup of the boiler, its nodes and its curves. Timed by a direct
  in-process loop over the recorded cases, both sides called through a C function pointer, best of
  15 interleaved runs.
