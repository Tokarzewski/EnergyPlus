# irexch-rs

Rust port of `irexch.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `IRExchange` (`irexch.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `HeatBalanceIntRadExchange::CalcInteriorRadExchange` from
`src/EnergyPlus/HeatBalanceIntRadExchange.cc`, which EnergyPlus runs for every radiant enclosure at
every iteration of the inside surface heat balance, for one enclosure of opaque surfaces and at
most one bare window:

- at the start of an environment, the inside emissivities and Hottel's ScriptF (by `CalcScriptF`,
  times the Stefan-Boltzmann constant) or, for the Carroll method, F' (`CalcFp`);
- the radiating temperatures (for a bare window at the first iteration, last time step's inside
  glass face) and the net long-wave radiation to each surface by ScriptF or the Carroll MRT;
- for the window, the long-wave radiation from the zone incident on it (`SurfWinIRfromParentZone`).

The enclosure is the box zone of `intrad-rs` (unit 20), whose zone, view factors
(`CalcApproximateViewFactors`, `FixViewFactors`), `CalcScriptF` and `CalcFMRT` are now public for
this (visibility only). It is a path dependency.

The oracle (`rust/oracles/irexch/`) sets up the enclosure as `InitInteriorRadExchange` does, with
the real view factor routines, then calls the real `CalcInteriorRadExchange` for the first
iteration at the start of an environment and, when asked, once more for a later iteration with
warmer surfaces. These return NaN in both (ADR-009): `which`, `carroll` or `iter` out of range, a
mask outside 1 to 127, a surface or window index outside the enclosure, FixViewFactors' fatal
error, and any input that is not finite or lies outside what EnergyPlus meets (dimensions outside
0.5 to 50 m, mass outside 0 to 500 m2 or under 0.5 m2 when included, rotation outside 0 to 360,
absorptances outside 0.05 to 0.99, temperatures outside -30 to 80 C, temperature steps outside -10
to 10 C).

Not ported yet: shaded, switchable, equivalent layer and BSDF windows, tubular daylighting
diffusers, movable insulation, window frames and dividers, representative surfaces, and partial
resimulation of one zone.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 245 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/irexch/`. Waived under ADR-007.
- **Recording, diff and gate:** 13839 cases in all: 13502 surfaces of random box zones plus
  rust-anything's generated cases. WSL kept going down and cutting long driver runs, so the cases
  were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13839/13839 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** slower than the C++, 0.71x: 8.98 us per call against 6.41 us. Each call also builds
  the enclosure, and most of that time is `intrad-rs`'s `FixViewFactors` iterations and ScriptF
  inversion, which EnergyPlus runs once per simulation, not the exchange loop it runs at every
  iteration. The exchange loop has not been timed on its own. Timed by a direct in-process loop
  over the recorded cases, both sides called through a C function pointer, best of 15 interleaved
  runs, on a loaded machine (load average 7 to 8).
