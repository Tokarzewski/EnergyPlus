# ksu-rs

Rust port of `ksu.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `KsuTsv` (`ksu.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ThermalComfort::CalcThermalComfortKSU` from `src/EnergyPlus/ThermalComfort.cc`,
which EnergyPlus runs for every People object with the KSU thermal comfort model at every zone
time step, for one People object:

- the KSU two-node model of the body's core and skin over a one hour exposure of an unacclimated
  man: `DERIV` (the thermoregulation signals, shivering, sweating with its iteration when the skin
  wettedness is over 0.4, skin conductance and the passive energy balance) integrated by `RKG`
  (Runge-Kutta-Gill, 0.01 h steps);
- the thermal sensation vote from the vasoconstriction or vasodilation it ends with, capped at 4;
- `CalcRadTemp` for an enclosure averaged MRT, with radiant heater gains to people;
- the relative humidity by `PsyRhFnTdbWPb`, from `psychrometrics-rs` (unit 1), and the saturation
  vapour pressure from `comfort-rs` (unit 10). Both are path dependencies.

Like the C++, `DERIV` reads the core and skin temperatures from the state, which are updated once
per step, not from the step's intermediate values.

The oracle (`rust/oracles/ksu/`) sets up one People object in one zone, flagged for the KSU model,
with constant activity, work efficiency, clothing (InsulationSchedule) and air velocity schedules,
an enclosure averaged MRT and the zone's comfort air temperature and humidity ratio, then calls the
real `CalcThermalComfortKSU`. Each case asks for the vote, the MRT or the operative temperature it
reports. These return NaN in both (ADR-009): `which` outside 0 to 2; any input that is not finite
or lies outside what EnergyPlus meets (barometric pressure outside 60000 to 110000 Pa, air or
radiant temperature outside -10 to 60 C, humidity ratio outside 0 to 0.05, radiant gain outside 0
to 2000 W, activity outside 50 to 900 W, work efficiency outside 0 to 0.5, clothing outside 0 to 3
clo, air velocity outside 0 to 5 m/s).

Not ported yet: the dynamic and calculated clothing types, surface weighted and angle factor MRT,
the non-mixing room air models' comfort temperature, and the loop over People objects.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: 363 lines of Rust (with tests) against
  a limit set by the 6-line C forwarder in `rust/oracles/ksu/`. Waived under ADR-007.
- **Recording, diff and gate:** 13788 cases in all: 4500 people, each asked for all three
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver
  runs, so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 13788/13788 match. The gate was run on a
  copy of this crate with the first 4000 cases: every check passes (behaviour 4000/4000) except
  size.
- **Speed:** 1.08x faster than the C++: 51.6 us per call against 55.7 us. Each call takes 100
  integration steps of five `DERIV` calls, whose time goes mostly to `pow` and `exp` from the same
  C library on both sides. Timed by a direct in-process loop over the recorded cases, both sides
  called through a C function pointer, best of 15 interleaved runs.
