# intconv-rs

Rust port of `intconv.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `IntConvCoeff` (`intconv.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `Convect::InitIntConvCoeff` from `src/EnergyPlus/ConvectionCoefficients.cc`
for one heat transfer surface in a zone with no air system. The inside heat balance runs it
before the iterations and every 30 iterations after that.

The inside convection coefficient comes from the model set on the surface or on its zone, each
held above `LowHConvLimit`:

- a user value;
- ASHRAE simple;
- TARP, using the ASHRAE and Walton natural convection correlations for opaque surfaces and
  ISO 15099 for windows (with its psychrometric air density and specific heat, and its EMS and
  frame ratio handling);
- ASTM C1340.

After that comes the EMS override. Exterior windows then get the frame adjustment ratio, a
second time for ISO 15099, as in the C++.

The correlations keep the C++ order of operations. One deliberate oddity is kept: ASTM C1340's
tilted roof case converts the tilt with the rounded pi 3.14159, exactly as the C++ does.
`pow`, `sin` and `exp` go to the same C library on both sides.

Not ported:

- scheduled and user curve coefficients;
- ceiling diffusers and Trombe walls, which are zone-wide;
- the adaptive convection algorithm;
- Kiva foundations;
- an air system's air change rate for ASTM C1340. The zone has no loop nodes, so the rate is
  zero.

The oracle (`rust/oracles/intconv/`) sets up one zone, one space and one surface, then calls the
real `InitIntConvCoeff`. These return NaN in both (ADR-009):

- flags outside 0 or 1;
- a model outside the list above;
- a user value set on the zone.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 345 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/intconv/`. Waived under ADR-007.
- **Recording, diff and gate:** 12370 cases in all: 12000 surfaces plus rust-anything's generated
  cases. WSL kept going down and cutting long driver runs, so the cases were recorded and diffed
  in chunks of 1500 with the crate's own driver (`.rust-anything/driver_c.py record` and `diff`).
  All 12370/12370 match. The gate was run on a copy of this crate with the first 4000 cases:
  every check passes (behaviour 4000/4000) except size.
- **Speed:** 2.13x faster: 49 ns per call against 104 ns for the C++. The C++ figure includes the
  oracle writing about 25 state fields before each call. Timed by a direct in-process loop over
  the recorded cases, both sides called through a C function pointer, best of 15 interleaved
  runs.
