# shadowinterior-rs

Rust port of `shadowinterior.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `ShadowInterior` (`shadowinterior.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```
## What is ported

`src/port.rs` ports a receiving surface with one window and up to two back surfaces, shaded by
one or two shadowing surfaces, as `src/EnergyPlus/SolarShading.cc` computes it: unit 33's
`SHADOW`, `SHDGSS` with `MULTOL`, `SHDBKS`, `SHDSBS` and `SHDRVL`, plus
`CalcInteriorSolarOverlaps`, which `SHDSBS` runs for a window whose construction transmits
(`TransDiff` above 0) once its sunlit area is known. For each back surface figure it runs
`MULTOL` of that figure on the window's figures (on its reveal's opening instead, copied over the
window's figures, when the reveal shades the window), and keeps each overlap area above 0.001,
times the window's glazed fraction, in `SurfWinBackSurfOverlaps`; a back surface that is a
subsurface (a window in the back wall) has its overlap taken off its base surface's. The simple
distribution (no overlaps) is taken with no back surfaces, an interzone receiving surface
(`ExtBoundCond` above 0) or too little figure space. The copy of the reveal figures covers
`MaxHCV` vertex slots, as the C++ loop does.

The oracle (`rust/oracles/shadowinterior/`) gives the real `SHADOW` unit 33's scene with the
window's construction transmittance, glazed fraction, the receiving surface's `ExtBoundCond`
and back surface 6's `BaseSurf` as inputs, and returns the first three overlap entries with
`FINSHC` and `NINSHC`; `SurfWinBackSurfOverlaps` is reset on every call. These return NaN in both
(ADR-009): unit 33's guards, a transmittance or glazed fraction outside [0, 1], an `ExtBoundCond`
outside 0 or 1, and a back surface 6 base other than 5 or 6.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails its size check: about 1450 lines of Rust
  against a limit set by the 6-line C forwarder in `rust/oracles/shadowinterior/`. Waived under
  ADR-007.
- **Recording and diff:** 17239 cases: 200 scenes as in unit 33 and 150 with the sun in front,
  two back surfaces and a window that transmits (108 scenes reach a back surface figure, 62 an
  overlap, 9 two overlaps, 6 a back window's overlap taken off its wall's). WSL went down every
  15 to 20 minutes and cut any run of rust-anything's driver longer than about a minute, so the
  cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`): 17239/17239 match. A whole `rust-anything
  gate` run was cut the same way every time, so the gate was run on a copy of this crate whose
  `cases.jsonl` holds the first 4000 cases: every check passes (behaviour 4000/4000) but size.
- **Speed:** 1.92x faster: 1727 ns per call against 3311 ns for the C++. The C++ side includes the
  oracle's per-call setup, which here also zeroes the whole `SurfWinBackSurfOverlaps` array (24
  hours by 20 by 6 surfaces), so the ratio overstates the port's lead over SolarShading's own
  code. Timed by a direct in-process loop over the recorded cases, both sides called through a C
  function pointer, best of 15 interleaved runs, under heavy load from other work (load average
  20 to 30).
