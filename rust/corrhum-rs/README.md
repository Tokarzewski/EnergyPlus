# corrhum-rs

Rust port of `corrhum.c`, bridged with the C ABI. Generated by rust-anything.

## Functions

- `CorrectHumRat` (`corrhum.c:8`)

## Loop

```sh
rust-anything record .   # record what the TS code does
rust-anything build .    # build the the C ABI module
rust-anything diff .     # run the recorded cases against Rust
rust-anything shadow .   # run both in the app, log mismatches
rust-anything gate .     # fmt, clippy, tests, unsafe, API, diff
```

## What is ported

`src/port.rs` ports `ZoneTempPredictorCorrector::ZoneSpaceHeatBalanceData::correctHumRat` from
`src/EnergyPlus/ZoneTempPredictorCorrector.cc` for a zone (not a space). The zone air moisture
balance runs it for every zone on every corrector step:

- the moisture and air mass flows from a controlled zone's supply air inlets, divided by the
  zone multipliers;
- the moisture balance coefficients from the latent gains and the infiltration, ventilation,
  cooling tower, earth tube, convection, mixing and outdoor air flows, and the air capacity from
  the air density, volume, moisture capacity multiplier and system time step;
- the new zone air humidity ratio under the third order, analytical or Euler zone air solution,
  set to 0 when the zone dries out and held at saturation at the zone air temperature;
- the system node's humidity ratio and enthalpy.

The psychrometric functions come from `psychrometrics-rs` (a path dependency).

The oracle (`rust/oracles/corrhum/`) sets up one zone, then calls the real function. These
return NaN in both (ADR-009):

- flags outside 0 or 1, inlet counts outside 0 to 3 and algorithms outside their enum;
- multipliers outside 1 to 10000, whose int product must not overflow;
- a negative air density, which EnergyPlus stops on as a fatal error (the oracle catches the
  `FatalError`).

Not ported yet: spaces, return and supply plenums and their leaks, parallel PIU leakage, the
AirflowNetwork, duct loss and RoomAirflowNetwork moisture terms, the hybrid model, and latent
sizing reports.

## Accepted gate exceptions (2026-11-23)

- **Size:** `rust-anything gate` fails only its size check: about 225 lines of Rust against a
  limit set by the 6-line C forwarder in `rust/oracles/corrhum/`. Waived under ADR-007.
- **Recording, diff and gate:** 12520 cases in all: 4000 zones, each asked for all three
  results, plus rust-anything's generated cases. WSL kept going down and cutting long driver
  runs, so the cases were recorded and diffed in chunks of 1500 with the crate's own driver
  (`.rust-anything/driver_c.py record` and `diff`). All 12520/12520 match. The gate was run on a
  copy of this crate with the first 4000 cases (its `psychrometrics-rs` path made absolute):
  every check passes (behaviour 4000/4000) except size.
- **Speed:** 0.96x, slightly slower: 56 ns per call against 54 ns for the C++, even though the
  C++ figure includes the oracle's per-call setup. As for `predhum-rs`, the likely cause is that
  the C++ caches saturation pressures, which `psychrometrics-rs` computes again. Timed by a
  direct in-process loop over the recorded cases, both sides called through a C function
  pointer, best of 15 interleaved runs.
